# GDD-06 局域网多人摆放（LAN Multiplayer）

## 1. 概述
同一局域网内多台电脑的猫出现在彼此桌面上：各玩家的猫（含装扮）同步渲染到其他人的屏幕，按排布算法协商摆放位置，支持敲击节奏同步与表情互发。技术选型 **WebSocket（JSON 消息）**，房主即服务器。不做对战/Battle Royale（超范围，协议留扩展字段）。

## 2. 目标
- 4 台机器联机，端到端状态同步延迟 **< 200ms**（局域网典型 < 20ms）。
- 加入/离开对其他玩家**无卡顿**（< 500ms 完成重排）。
- 断网/崩溃不损坏任何本地数据；会话纯临时（不持久化联机世界）。
- 零配置：同网段发现（UDP 广播）+ 6 位房间码兜底。

## 3. 输入
- 本地状态变更：装扮、敲击事件、表情、拖动自猫位置。
- 网络消息（见 6.3 协议）。
- 玩家操作：创建房间 / 加入房间（房间码或自动发现）/ 离开。

## 4. 输出
- 远端猫渲染（每只远端猫 = 独立小窗或主窗内子区域，由渲染层决定——开放问题 1）。
- 房间状态 UI：成员列表、名字牌、当前排布模式。
- 敲击音效（远端猫音量按距离衰减或固定低音量，默认固定 30%）。

## 5. 规则
- **房间模型**：房主 = 服务器（权威）；客户端只上报意图，房主仲裁位置与冲突。上限 **8 只猫**。
- **槽位协商（排布算法）**：房主根据成员数与各玩家主屏分辨率计算槽位：
  - Grid（网格）/ BorderLine（屏幕底边一排）/ AroundBorder（沿四边）/ Free（自由坐标）/ Random / AlignedWithHost（对齐房主猫旁）。默认 BorderLine。
  - 槽位以**归一化屏幕坐标**（0-1）下发，各客户端按自己分辨率换算，保证跨分辨率一致。
  - Free 模式下玩家可拖动自己的猫，坐标上报房主，房主做防重叠校验（重叠 > 30% 则退回最近空位）。
- **同步频率**：敲击事件为事件驱动（发生即发）；位置变化节流 10Hz；心跳 2s。
- **断线处理**：
  - 客户端 5s 无心跳 → 房主移除其猫并广播重排；客户端侧 5s 无房主心跳 → 提示"连接断开"并自动清空远端猫，本地一切功能不受影响。
  - 房主离开 → 会话结束（V1 不做房主迁移），客户端收到 `SESSION_END` 后优雅清场并提示。
- **隐私/安全**：消息只含装扮 id 与坐标，不传文件；物品 id 校验合法性（未拥有装扮的猫显示默认皮肤，防伪造——装扮权威数据在各自本地，远端仅展示）；端口固定 47821（UDP 发现）/ 47822（TCP WebSocket）。

## 6. 数值框架
### 6.1 参数表
| 参数 | 默认值 | 说明 |
|---|---|---|
| maxCats | 8 | |
| heartbeatIntervalMs | 2000 | 超时阈值 ×2.5 = 5000ms |
| positionRateHz | 10 | 位置上报节流 |
| udpDiscoveryPort | 47821 | 广播间隔 1s |
| wsPort | 47822 | |
| reconnectWindowMs | 10000 | 断线重连窗口，超时视为离开 |

### 6.2 消息 envelope
```json
{ "v": 1, "type": "CAT_TAP", "from": "playerUuid", "seq": 1234, "ts": 1730000000000, "payload": { } }
```

### 6.3 协议草案（消息类型）
| type | 方向 | payload | 说明 |
|---|---|---|---|
| DISCOVER | C→广播 | {roomCode?} | UDP 发现；带 roomCode 则定向 |
| OFFER | C→H | {name, uuid} | 请求加入 |
| WELCOME | H→C | {yourSlot, layoutMode, members[]} | 分配槽位与全量成员快照；members[].name = 宠物名 |
| MEMBER_JOIN / MEMBER_LEAVE | H→All | {member} | 成员变更（name = 宠物名） |
| LAYOUT_SET | H→All | {mode, slots{uuid→normPos}} | 排布变更/重排 |
| CAT_STATE | C→H→All | {outfit{skin,hat,bongos}, mirror} | 装扮快照，变更时发 |
| CAT_TAP | C→H→All | {side} | 敲击同步（低优先级，可丢） |
| EMOTE | C→H→All | {emoteId} | 表情互发 |
| HEARTBEAT | 双向 | {} | 存活 |
| PING/PONG | 双向 | {ts} | RTT 测量，UI 显示信号格 |
| SESSION_END | H→All | {reason} | 房主结束会话 |
| KICK | H→C | {reason} | 房主移除成员 |

### 6.3.1 宠物名（E9，向后兼容扩展）
- **名字字段**：名册条目/Hello/MemberJoin 的 `name` 语义升级为**宠物名**，新客户端发送上限
  **UTF-8 24 字节**（12 个字素封顶，CJK 8 字）；接收端仍接受旧客户端的 48 字节显示名，
  展示层按 `PetNameRules` 清洗，空/坏名回退物种默认名。
- **不改线格式**：复用既有 UTF-8 长度前缀名称字段，**不新增字段、不 bump 帧版本**。
  旧服务器只当普通显示名转发；旧客户端只当普通名字展示——新→旧、旧→新均不断连。
- **改名时机**：房间内改名不新增广播消息（未知消息类型会让旧客户端断开）；
  本地成员表即时刷新，**对端在下次进入房间收到 Welcome 名册快照时生效**。
- **服务器**：无需改动（哑中继按既有 name 字段透传）。

### 6.4 带宽估算
8 只猫稳态：心跳 8×0.5B/s 有效负载 + 敲击事件（峰值 8 键/s × ~60B）≈ **< 2 KB/s**，可忽略。

## 7. 边界情况
- **同名/同 uuid 冲突**：uuid 碰撞几乎不可能；重名自动加后缀"（2）"。
- **IP 变更（DHCP）**：连接层用 uuid 识别成员，短暂掉线在 reconnectWindow 内保留槽位。
- **防火墙拦截**：首次创建房间时提示添加防火墙规则（给出一条 netsh 命令文案供用户复制，程序不自动提权）。
- **跨网段/校园网隔离**：UDP 发现失败 → 房间码直连（输入房主 IP:端口 或 6 位码由房主口头告知）。
- **恶意消息/格式错误**：所有消息严格 schema 校验，非法即断开该连接；单客户端消息频率 > 50/s 断开（防刷）。
- ** 远端装扮 id 不存在**：降级为默认皮肤渲染，不影响会话。
- **系统休眠**：恢复后心跳超时自动清场/重连，无需人工干预。

## 8. 开放问题
1. 远端猫渲染：独立透明小窗（隔离好、窗口数多）vs 单窗内子视图（窗口少、需自绘合成）？需程基岩评估 WPF 多透明窗的性能上限。
2. 房主迁移（原房主退出后会话延续）是否纳入 V3？建议先不做，架构预留 host 选举字段。
3. 敲击同步是否合并节流（如 50ms 内多击合并为一次"快敲"）？建议实现层做合并，协议不变。
4. 互赠礼物（原作有）：协议已留 EMOTE/扩展位，V3 视进度决定。
