# 技术风险清单

> 评级：概率 × 影响。每条附缓解措施与负责人阶段。评审节奏：每 Epic 结束复查一次。

## R1 管理员权限程序上输入捕获失效 ⚠️ 最高优先级
- **风险**：若用低级键盘钩子（WH_KEYBOARD_LL），管理员权限进程的按键因 UIPI 隔离收不到——玩家以管理员身份玩游戏很常见，桌宠静默失灵且无报错。
- **决策**：ADR-002 已选 GetAsyncKeyState 轮询规避（异步键状态表不受 UIPI 限制）。
- **残留风险**：极少数反作弊内核驱动环境（受保护进程）可能屏蔽。无法完全解决。
- **缓解**：设置面板内置"输入自检"（点击后 5s 内打字 → 显示检测到的按键数）；检测长时间 0 输入时 UI 提示排查指引。
- **验证**：Story E1-S4 验收标准含"以管理员权限运行的记事本中打字，猫正常敲鼓"。

## R2 DPI 缩放与多显示器
- **风险**：Windows 10/11 混合 DPI（125%/150%/200% 混用）下 WPF 若非 PerMonitorV2 aware，猫在副屏会模糊或尺寸漂移；位置按像素持久化会在分辨率/DPI 变更后跑偏。
- **缓解**：
  1. `app.manifest` 声明 `PerMonitorV2`，禁用 `AppContext` 旧 DPI 行为；`HwndSource` 上处理 `WM_DPICHANGED` 重新计算窗口尺寸。
  2. 位置存**比例**（0~1 相对主屏工作区，ADR-004），不存像素。
  3. 启动时 `Screen.AllScreens` 枚举边界，猫落在任何监视器外 → 回中（对齐原作机制）。
  4. 多屏切换热键（F8 对齐原作行为，可配置）列入 E1 Story。
- **验证**：E1-S6 验收含"4K 主屏 + 1080p 副屏、主屏 150%/副屏 100%，拖动跨屏不模糊、重启位置还原"。

## R3 WPF 透明窗口性能 / DWM 失效
- **风险**：DWM 透明失败回退色键模式后素材异常（含色键色像素透穿）；或 AllowsTransparency 误用导致软件渲染 CPU 飙升。
- **缓解**：ADR-001 已锁 HwndSource+DWM 路线并禁止 AllowsTransparency；色键素材像素扫描进构建脚本；性能预算立卡（见下）。
- **性能预算**（超预算即开剖析）：空闲 CPU < 1%，敲击时 < 3%；空闲内存 < 120MB；启动到猫可见 < 2s。CI 记录启动耗时基线。

## R4 杀软 / SmartScreen 误报
- **风险**：全局输入轮询 + 置顶透明窗口的组合命中杀软启发式；无签名 exe 触发 SmartScreen 拦截，影响分发。
- **缓解**：
  1. 输入侧选轮询而非低级钩子（降低键盘记录器特征匹配，ADR-002 论证）；
  2. 发布版代码签名（EV 证书成本高，起步可用 OV + 累积信誉）；至少 Authenticode 签名 + 固定版本号递增；
  3. 提交 Microsoft 安全情报误报申诉通道与主流杀软白名单申请；
  4. 避免行为叠加：不读进程列表、不写注册表 Run 键以外的敏感位置（自启动用注册表 Run，用户可关，设置面板明示）；
  5. 风险记录进分发文档，首版灰度小范围收集误报样本。

## R5 存档损坏与数据丢失
- **风险**：断电/崩溃时写档中断导致 JSON 半截；玩家手改档引入非法状态。
- **缓解**：ADR-004 原子写入（tmp + File.Replace）+ .bak 轮换 + checksum + 安全模式；**绝不静默清档**。测试覆盖：写档中途 kill 进程 ×1000 次的混沌测试（E4-S2）。

## R6 引擎/框架选型风险：WPF 能力天花板
- **风险**：后续若要做 GIF 导出、复杂粒子表情、跨平台（玩家要 Mac 版的声音一直存在于此类项目社区）。
- **缓解**：Core 层零 WPF 依赖（编译期强制）；渲染/音频/输入均走接口（module-map），替换实现不伤玩法逻辑。GIF 导出 V2 评估时引入 SkiaSharp 仅作导出工具（ADR-003 已预留）；跨平台**明确不做**，若立项走新仓库，不在本架构背债。

## R7 .NET 8 与打包
- **风险**：.NET 8 是 LTS 但框架依赖/自包含、修剪（trimming）对 WPF 支持有限，发布体积可能 > 150MB。
- **缓解**：发布用自包含 + ready-to-run，不做 trimming（WPF 反射面广，修剪收益低风险高）；体积预算 < 180MB；single-file 可选。安装器用 Inno Setup / MSIX 二选一（E8 前决策，MSIX 对自启动/卸载更干净但调试链路长）。

## R8 联机协议被滥用（V3）
- **风险**：局域网内恶意客户端发畸形包/超包导致房主崩溃或内存耗尽。
- **缓解**：ADR-005 已定：payloadLen 上限 256KB、读前校验、房主权威、所有来包按不可信输入、协议 fuzz 测试进 CI（Protocol.Tests 含随机字节流不崩溃断言）。

## R9 平衡数值与素材管线缺位（非纯技术，技术侧联动）
- **风险**：分析报告 §6 指出原作掉率/配方数值未解析（也不应解析）——数值需自设计；素材需原创管线，部件位图规格（尺寸/锚点/命名）若无规范，渲染层返工。
- **缓解**：数值走 `Core/Config/*.json` 数据驱动 + 平衡表评审（与文策渊对齐）；素材规格由我在 E1-S1 交付 `docs/art-spec/cat-parts-spec.md` 前置卡点：PNG 尺寸、透明通道、部件锚点坐标约定、punch 帧对位。

## R10 轮询 CPU 占用回潮
- **风险**：轮询方案（ADR-002）若空闲降频实现失误，常驻 8ms 循环会烧 2-5% CPU，桌宠变"电费猫"。
- **缓解**：双频 + 空闲判定 + 窗口隐藏挂起（ADR-002/003）；性能预算 R3 内含空闲 CPU 指标；PerfView 空闲剖析进 E1 验收。
