# ADR-004 存档方案

状态：Proposed｜日期：2025｜决策人：程基岩

## 上下文
需要持久化：猫位置（按屏幕比例）、设置、金币、库存物品（含品质）、图鉴进度、预设、挂机掉落计时、（V3）通行证进度。原作用 Steam 云存档 + 注册表位置偏好（`BongoCatPosXRel/YRel`）；复刻为单机 → 本地存档 + 自选云同步不在范围内。数据量小（< 1MB），人工可编辑调试是加分项。

## 备选方案

### A. SQLite
- 优点：事务、查询。
- 缺点：引入原生 e_sqlite3 依赖；对 <1MB 的文档型数据过度设计；玩家不可读；图鉴/库存本质是文档不是关系表。排除。

### B. 注册表
- 原作用于位置偏好。缺点：不可导出、不可版本化迁移、玩家无法备份、混存 JSON 物品数据非常痛苦。仅位置一个值不值得引入持久化双轨。排除。

### C. JSON 文档 + 原子写入 ✅
- `System.Text.Json`（BCL 内置、源生成器 `JsonSerializerContext` 支持 AOT/修剪、无第三方依赖——原作用 Newtonsoft 但我们没有理由带两个 JSON 库）。
- 可读、可 diff、可手改调试（开发期价值大）。

## 决定
**方案 C**。

### 布局
```
%APPDATA%\BongoCatRemix\       （Environment.SpecialFolder.ApplicationData）
├── save.json          主存档（经济/库存/图鉴/通行证/掉落计时）
├── presets\*.json     整套装扮预设
└── settings.json      设置（轮询、音量、开机自启、透明模式覆盖）
```

### 可靠性规则（逐条可执行）
1. **原子写入**：写 `save.json.tmp` → `File.Replace`（有旧文件）/`File.Move`（首次），任一时刻磁盘上必有一个完整存档。
2. **版本字段**：顶层 `"schemaVersion": N`；迁移器 `ISaveMigrator` 链式升级（N→N+1），未知未来版本只读不写并提示。
3. **节流落盘**：变更打脏标记；30s 定时器 + 退出（SessionEnding + ProcessExit）强制保存；崩溃最多丢 30s 经济进度，可接受。
4. **备份**：每次成功保存后滚动保留 `save.json.bak`（上一版）；启动时主文件损坏 → 自动尝试 `.bak` → 再失败进入安全模式（内存运行 + UI 红点提示，**绝不静默清档**）。
5. **校验**：写入前用源生成器的 Serializer 序列化 + 文件尾写 `"checksum": <crc32 of payload>`，加载时校验不匹配则视为损坏走备份路径。
6. 存档目录可被 `--portable` 命令行参数重定向到 exe 旁（便携版用户）。

### 位置记忆
猫位置按主屏工作区**比例**（0~1 浮点）存储，启动时按当前分辨率还原；越界检测：启动时若落在任何监视器外 → 回中（对应原作"监视器边界枚举与越界回中"机制，原创实现）。

## 后果
- 单线程写模型：所有存档变更经 `ISaveService` 排队（App 层 `SemaphoreSlim`），禁止旁路写文件。
- 存档内**不含**反作弊需要的强完整签名（单机游戏，玩家改档自担；V3 多人仅同步临时状态不同步存档）。
- `System.Text.Json` + 源生成器在首次编译时固定 schema，字段改名要过迁移器，PR 检查清单加入"改 SaveModel 必须动 Migrator"。
